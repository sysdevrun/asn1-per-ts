# Generating TypeScript from ASN.1

Turn an ASN.1 module into a TypeScript file of named types and typed codecs.
This is the option to reach for when the schema comes from a `.asn` file: it is
the only one that gives types to a schema the compiler never sees as a literal,
and it is the cheapest of the three to compile.

## Running it

```bash
npx tsx cli/generate-types.ts ticket.asn src/generated/ticket.ts
```

The input may be an `.asn` file or a `.json` registry of `SchemaNode`s, as
produced by `cli/generate-schema.ts`. With no output path the module is written
to stdout.

| Flag | Meaning |
|---|---|
| `--import-from <spec>` | Import specifier for the runtime. Defaults to `asn1-per-ts`. |

The generator is also exported, so you can wire it into your own build:

```typescript
import { generateTypeScript, parseAsn1Module, convertModuleToSchemaNodes } from 'asn1-per-ts';

const module = parseAsn1Module(asnText);
const code = generateTypeScript(convertModuleToSchemaNodes(module), {
  moduleName: module.name,
});
```

## What it emits

For this module:

```asn1
Sample-Module DEFINITIONS AUTOMATIC TAGS ::= BEGIN

  Sales-Channel ::= ENUMERATED { online, counter, mobile, ... , partner }

  Issuing-Detail ::= SEQUENCE {
    issuer-num      INTEGER (1..32000),
    issuing-year    INTEGER (2016..2269) DEFAULT 2024,
    security-token  OCTET STRING (SIZE(1..64)) OPTIONAL,
    channel         Sales-Channel,
    ...
  }

END
```

you get:

```typescript
// Generated by asn1-per-ts. Do not edit by hand.
// ASN.1 module: Sample-Module

import { createCodecs } from 'asn1-per-ts';
import type { SchemaRegistry, TypedCodec } from 'asn1-per-ts';

/** ASN.1 `Sales-Channel`. */
export type SalesChannel = "online" | "counter" | "mobile" | "partner";

/** ASN.1 `Issuing-Detail`. */
export interface IssuingDetail {
  "issuer-num": number;
  "issuing-year": number;
  "security-token"?: Uint8Array;
  channel: SalesChannel;
}

/** Encoding input for IssuingDetail: DEFAULT fields may be omitted. */
export interface IssuingDetailInput {
  "issuer-num": number;
  "issuing-year"?: number;
  "security-token"?: Uint8Array;
  channel: SalesChannelInput;
}

export const schemas: SchemaRegistry = { /* … */ };

export const codecs = createCodecs(schemas) as unknown as {
  "Sales-Channel": TypedCodec<SalesChannel, SalesChannelInput>;
  "Issuing-Detail": TypedCodec<IssuingDetail, IssuingDetailInput>;
};
```

Then:

```typescript
import { codecs } from './generated/ticket.js';

const hex = codecs['Issuing-Detail'].encodeToHex({
  'issuer-num': 42,
  channel: 'mobile',
  // issuing-year omitted — DEFAULT 2024
});

const detail = codecs['Issuing-Detail'].decodeFromHex(hex);
detail['issuing-year']; // number — always present after decoding
```

## The `Input` variant

Every type `X` comes with an `XInput`. They differ in exactly one way: a
DEFAULT field is required in `X` (the decoder always supplies it) and optional
in `XInput` (the encoder may omit it). Where a type has no DEFAULT anywhere
beneath it, `XInput` is a plain alias:

```typescript
export type SalesChannelInput = SalesChannel;
```

## Naming

ASN.1 identifiers allow hyphens; TypeScript type names do not.

- **Type names** are rewritten to PascalCase: `Sales-Channel` → `SalesChannel`.
  Collisions get numbered (`FooBar`, `FooBar2`), and names that would shadow a
  global or the generated file's own imports get a trailing underscore
  (`TypedCodec` → `TypedCodec_`).
- **Field names** are preserved exactly and quoted where necessary, so the
  generated types match the decoded objects key for key.
- **Registry keys** keep the original ASN.1 names, which is why `codecs` is
  indexed as `codecs['Issuing-Detail']`.

## Named types, not inlined structures

The ASN.1 parser resolves type references by expanding them, so by the time a
schema reaches the generator every mention of `Issuing-Detail` has become its
full structure. The generator matches those structures back to the types they
came from, so the output references `IssuingDetail` rather than repeating it.

That is what makes generated code cheap and readable: on a 150-type schema it
costs about 20k type instantiations against 109k for the equivalent inline
`SchemaNode` literal, and a type error names `IssuingDetail` instead of
printing its entire shape.

Two structurally identical ASN.1 types collapse onto the first one declared.
They describe the same values, so this is safe, but the second name will not
appear in the output.

## Limitations

- **Metadata trees are not typed.** `decodeWithMetadata` on a generated codec
  returns a plain `DecodedNode`. Typing the tree would mean a third interface
  per type; use the DSL or `InferMetadata` if you need it.
- **Constraints are not in the types.** Value and size constraints are enforced
  at runtime by the codecs. TypeScript has no integer range types.
- **Regenerate after editing the `.asn`.** Nothing checks that the generated
  file is current. Wire the generator into your build, or check the output in
  and assert it round-trips — this repository does the latter, in
  `tests/codegen/generatedModule.test.ts`.
